## 〇、如何用本文档（必读）

> 本文档是**整个项目的唯一方向基准**。一切以本文档为准。

**硬性约定：**
1. **本文档即契约**：实现前先核对本文档；冲突时以本文档为准；认为文档有误，先修订文档再改代码。
2. **不得偏离已定决策**：技术栈、数据模型、编辑引擎路线是已拍板的，不得擅自更换。
3. **无死代码**：格式识别用动态代码（任意格式都成立），**不做固定枚举**；禁止无用的占位/死分支/死文件。
4. **保持灵活性**：新增功能按可插拔模块接入，不得为某个功能破坏通用架构。
5. **文档随实现演进**：每完成一个功能，回来更新对应章节。

## 一、技术栈

> 选型原则：**本地优先、离线可用、不依赖云服务、不跳转第三方编辑**。格式保真与中文健壮性为硬指标。

### 1.1 运行框架

| 层次 | 选型 | 说明 |
|------|------|------|
| 桌面壳 | **Electron** | 跨平台，可调用本地文件；个人本地工具首选 |
| 前端界面 | **Vue 3 + TypeScript + Vite** | 组合式 API，组件化 |
| UI 组件库 | **Element Plus** | 中文生态成熟，表单/表格齐全 |
| 状态管理 | **Pinia** | 轻量，管理项目/插槽树/文件全局状态 |

### 1.2 数据与文件

| 能力 | 选型 | 说明 |
|------|------|------|
| 项目元数据 | **项目内 `project.json`** | 文件夹自包含、可整体搬移；不依赖外部数据库 |
| 本地文件操作 | **Node.js `fs`** | 复制、打包、目录 |
| 批量打包 | **`archiver`** | 导出 ZIP（扩展） |

### 1.3 文档编辑引擎（核心，保真关键）

> **保真策略**：**全程在原始文档上"原位编辑"，绝不重新序列化文档**。

| 能力 | 选型 | 说明 |
|------|------|------|
| Word 原位编辑 | **JSZip + 原生 `document.xml` 操作** | 打开 docx(zip) → 只改 `<w:t>` 文本 → 塞回原 zip；样式/字体/表格零改动 |
| Excel 原位编辑 | **SheetJS（xlsx）** | 程序内单元格编辑，保留工作簿结构 |
| CSV 原位编辑 | **自研纯文本引擎** | 解析二维网格（处理引号内逗号）→ 改单元格 → 序列化写回 |
| 中文处理 | 全链路 **UTF-8 原生** | CJK 全角/半角、混排换行；字段识别兼容中文标签与全角冒号 |

> **能力边界（如实标注）**：
> - ✅ **改已有文字 / 改表格单元格**：格式 100% 保真（只换文本，不动样式）。
> - ⚠️ **docx 重复文本替换**：字面替换，重复文本时可能命中错处（如实上报 missed）。
> - ⚠️ **老式 doc/xls（二进制）**：应用内**查看**（详情 + 系统程序打开）；不承诺原位编辑。

### 1.4 格式识别（动态、无枚举、无死代码）

> **核心原则**：格式 = 文件扩展名（小写）。**任意扩展名都成立**，不做固定枚举。
> 例：`报告.DOCX` → `docx`；`图纸.dwg` → `dwg`；`压缩包.zip` → `zip`。
> 上传什么格式就是什么格式，软件不为任何格式写死代码。

**编辑/预览能力判定**（"用哪个引擎"，非格式枚举）：
- 可应用内原位编辑：`csv / docx / docm / dotx / xlsx / xlsm / xltm`
- 老式二进制（查看 + 系统打开）：`doc / xls`
- 其他格式：查看（详情卡片）+ 系统程序打开 + 下载

## 二、项目架构与数据模型

### 2.1 目录结构（代码）

```
PPIMS/
  core/                 ← 核心管理层（类型/store/服务/IPC）
    types.ts            ← 数据模型（单一事实源）
    util.ts             ← 纯工具（动态格式/重名加序号/大小）
    classify.ts         ← 分类纯逻辑
    template-mapping.ts ← 项目→结构模板映射
    stores/             ← Pinia store（project/app）
    services/           ← docx-engine / xlsx-engine / csv-engine / fs / template-service
    ipc.ts / preload.ts / api.d.ts / main.ts
  features/             ← 功能层（Vue 组件）
    RootSetup / ProjectList / ProjectDetail / SlotTreePanel /
    SlotWorkspace / FilePanel / FileEditor / TemplateManager /
    SearchPanel / SlotStructureEditor
  dev/
    scripts/            ← build-electron / gen-icon / derive-icons
  docs/                 ← 本文档
  README.md
```

### 2.2 数据模型（v1.0.0）

```
Project
├─ info: ProjectInfo         // 名称/编号/地区/阶段/类型/下发时间/备注/分类取值/归档完成(v1.2.4)
├─ rootPath                  // 本机绝对路径（不入 project.json 关键数据）
├─ slots: Slot[]             // 顶层插槽（= 阶段）
├─ schemaVersion: 2          // v1.0.0 新数据模型
└─ createdAt / updatedAt

Slot（统一节点，可嵌套成多级树）
├─ id / name / order
├─ files: FileEntry[]        // 插槽下的文件（1..n，各自独立命名）
└─ subSlots: Slot[]          // 子插槽（多级树）★

FileEntry（独立文件，无版本/无状态）
├─ id
├─ name                      // 显示名（重名自动加序号：任务书 → 任务书_2）
├─ format                    // 动态格式（扩展名，非枚举）
├─ size                      // 字节（自动）
├─ createdAt                 // 上传时间（自动）
├─ updatedAt?                // 编辑后保存时间
├─ path                      // 相对项目根 POSIX 路径（<插槽文件夹>/<文件名>，如 阶段1/勘测大纲/任务书.docx）
├─ remark?                   // 描述/备注
└─ tags: string[]            // 自定义标签（"重要""已核"…）★

StructureTemplate（结构模板 = 阶段 + 插槽树，无模板文件）
├─ id / name / description
├─ structure: TplSlotInput[] // 纯结构：name + subSlots（无 id/files/order）
└─ createdAt / updatedAt
```

**v1.0.0 删除的类型/常量**：`FileStatus`、`Necessity`、`FileFormat`(枚举)、`QUALIFIED_STATUSES`、`NECESSITY_WEIGHT`、`STATUS_LABEL`、`NECESSITY_LABEL`、`FORMAT_LABEL`、`FileInstance`、`Stage`、`Template`、`ProjectTemplate`、`TplStageInput`、`progress`/`stageProgress`/`projectProgress`、`PRESET_STAGES`、`SCHEMA_VERSION=1`。

### 2.3 存储模型（v1.2.2：嵌套镜像，所见即所得）

```
项目根/
  project.json              ← 插槽树 + 文件清单（单一事实源）
  <顶层插槽名>/              ← 顶层插槽 = 一个文件夹
    <文件名>                 ← 该插槽下的文件（按"自动编号后的显示名 + 扩展名"命名）
    <子插槽名>/              ← 子插槽 = 嵌套文件夹
      <文件名>
```

> **嵌套镜像**：插槽树直接映射为磁盘目录。`FileEntry.path = <插槽文件夹>/<文件名>`（相对项目根）。
> **实时落盘**：加插槽→建文件夹；删插槽→递归删文件夹（含子插槽 + 全部文件）；改插槽名→改文件夹名（级联更新子树文件 path）；上传→存入所属插槽文件夹。任何变动即时写磁盘。
> **可搬移**：整个项目文件夹自包含（project.json + 插槽目录树），无绝对路径，整体拷走即用。
> **兼容**：加载旧项目（v1.0.0–v1.2.1 扁平 `files/`）自动迁移到嵌套结构（物理移动 + 更新 path + 补齐插槽文件夹，idempotent）。

### 2.4 分类维度（根级配置）

- 维度是项目的**分类字段**（如"地区""专业""客户"），只用于列表**分组/筛选/排序**。
- 维度**用户自定义、可扩展**（`dim_` 前缀 + 稳定 id），取值自由文本。
- 系统**不预置业务维度**，由用户按需定义（存 `<root>/ppims.json`）。

## 附录：设计决策记录（ADR 摘要）

| ADR | 决策 | 理由 |
|-----|------|------|
| 1 | 定位改为个人归档版 | 用户实际需求是"归档已完成文件"，非"跟踪完成度" |
| 2 | 插槽统一为可嵌套树（阶段 = 顶层插槽） | 用户要求"插槽可嵌套"，阶段与插槽统一更简洁 |
| 3 | 文件删除状态/版本/必要性 | 归档场景不需要流转；多文件各自独立命名 |
| 4 | 格式动态识别（扩展名即格式） | 用户要求"识别所有格式、不做固定枚举、无死代码" |
| 5 | doc/xls 只查看不编辑 | 二进制格式原位编辑需外部引擎，成本高；查看已覆盖需求 |
| 6 | 结构模板 = 阶段 + 插槽树（无模板文件） | 用户要求"结构模板不含模板文件" |
| 7 | 文件扁平存 files/（**v1.2.2 已被取代**） | 原始意图便于搬移、避免多级目录复杂度；v1.2.2 按用户期望改为"嵌套镜像"（见 ADR #23），旧数据自动迁移（ADR #25） |
| 8 | 数据模型 v1.0.0 不兼容旧版 | 大版本升级，用户接受直接新模型 |
| 9 | 测试用 vitest + Node 原生独立脚本（**v1.2.5 已移除**） | 原为环境限制（esbuild 无法 spawn）时用 Node 原生 TS 类型剥离跑纯逻辑；v1.2.5 清理时随测试套件一并移除（构建不再以测试为必需步骤） |
| 10 | v1.1.0 删除内置编辑，只外部预览/编辑 | 用户反馈"内置编辑做得太烂"，交给 Word/Excel 等专业工具更可靠 |
| 11 | v1.1.0 软件自带预置模板 | 用户反馈"软件很空不易上手"，预置一套开箱即用 |
| 12 | v1.1.0 托盘 + 桌面悬浮框 | 用户要求"缩小到菜单栏 + 桌面悬浮未完成归档项目" |
| 13 | v1.2.0 托盘图标多候选路径加载 | 打包后 public/ 不在原路径，Vite 拷到 dist/；多候选保证开发/打包都有图 |
| 14 | v1.2.0 悬浮框右上角 + fade-in + showInactive | 用户要求"右上角平滑展示、不覆盖应用"；showInactive 不抢焦点，fade-in 不闪屏 |
| 15 | v1.2.0 托盘设置菜单（开机自启 + 点关闭缩小到菜单栏） | 用户要求"把重要设置放设置菜单"；loginItem 管自启，closeToTray 管关闭行为 |
