## 〇、如何用本文档（必读）

> 本文档是**整个项目的唯一方向基准**。后续实现工作将在**其他对话**中由 AI **逐阶段完成**，那些对话**不共享本对话的上下文**——因此**一切以本文档为准**。

**给实现方（AI/开发者）的硬性约定：**

1. **本文档即契约**：实现任何功能前，先核对本文档对应章节；凡与本文档冲突的临时想法，**以本文档为准**；若你认为本文档有误或缺失，**先修订本文档、再改代码**，禁止"代码先行、文档后补"。
2. **不得偏离已定决策**：第一章技术栈、第二章架构、附录 ADR 中的决策是**已拍板**的，实现时不得擅自更换技术栈、数据模型或编辑引擎路线。
3. **按阶段推进、按验收标准交付**：第三章"阶段进度"定义了 P0 地基与功能状态板；每个阶段/功能都带**验收标准**，**达成验收标准才算完成**，不得以"基本可用"糊弄。
4. **保持灵活性**：新增功能一律按"可插拔模块"接入，**不得为某个功能破坏通用架构**（例如不得把勘测业务写死进核心）。
5. **文档随实现演进**：每完成一个阶段，回来更新第三章对应状态与附录；新增决策补入 ADR。

**文档结构总览**：第一章定**用什么技术**，第二章定**怎么组织**，第三章定**做到什么程度、怎么验收**，第四章定**未来往哪扩**，附录是**决策留痕**。

## 一、技术栈

> 选型原则：**本地优先、离线可用、不依赖云服务、不跳转第三方编辑**。格式保真与中文健壮性为硬指标。

### 1.1 运行框架

| 层次 | 选型 | 说明 |
|------|------|------|
| 桌面壳 | **Electron** | 跨平台（Win/macOS/Linux），可调用本地文件、本地服务；个人本地工具首选 |
| 前端界面 | **Vue 3 + TypeScript + Vite** | 组合式 API，组件化，便于功能模块独立开发 |
| UI 组件库 | **Element Plus** | 中文生态成熟，表单/表格/树形控件齐全，契合"表单类资料管理"场景 |
| 状态管理 | **Pinia** | 轻量，管理项目/阶段/槽位/文件全局状态 |

### 1.2 数据与文件

| 能力 | 选型 | 说明 |
|------|------|------|
| 项目元数据 | **项目内 `project.json`** | 文件夹自包含、可整体搬移；不依赖外部数据库 |
| 本地文件操作 | **Node.js `fs` / `fs-extra`** | 复制、移动、打包、目录扫描 |
| 全文检索 | **SQLite FTS5**（可选，P0 外） | 跨项目/跨文件检索；P0 先用文件级索引 |
| 批量打包 | **`archiver`** | 按阶段/按状态导出 ZIP |

### 1.3 文档编辑引擎（核心，保真关键）

> **保真策略**：**全程在原始文档 XML 上做"原位文本替换"，绝不重新序列化文档**。这是"下载结果与模板格式一致"的最强保证。

| 能力 | 选型 | 说明 |
|------|------|------|
| Word 解析/写回 | **JSZip + 原生 `document.xml` 操作** | 打开 docx(zip) → 只改 `<w:t>` 文本节点 → 塞回原 zip；样式/字体/表格/页边距零改动 |
| Word 结构识别 | 自研规则引擎（按 `Heading` 样式 / 加粗大字 / 表格首行推断章节与字段） | 智能推断 + 可手动微调边界 |
| Excel 编辑 | **Univer**（或 SheetJS 兜底） | 程序内单元格编辑、增删行列、保留工作簿结构，导出 xlsx |
| 复杂文档兜底 | **OnlyOffice Document Server**（可选嵌入，独立进程） | 复杂图文混排/嵌套表格的完美编辑；体积大，按需启用 |
| 中文处理 | 全链路 **UTF-8 原生** | CJK 全角/半角、混排换行、字数统计单独处理；字段识别兼容中文标签与全角冒号 |

> **能力边界（如实标注）**：
> - ✅ **改已有文字 / 填空 / 改表格单元格**：格式 100% 保真（只换文本，不动样式）。
> - ⚠️ **自动识别字段边界**：启发式推断，复杂文档可能需手动微调。
> - ⚠️ **新增整段/整行/整表**：无原始格式可继承，克隆邻近样式尽力一致。
> - 上述 ⚠️ 场景在 OnlyOffice 兜底层可完美达成。

### 1.4 格式转换（扩展，依赖本地软件）

| 转换 | 方式 | 依赖 |
|------|------|------|
| Word → PDF | Office COM / LibreOffice 命令行 | 本地 Office 或 LibreOffice |
| CAD → PDF | AutoCAD COM / 第三方 | 本地 AutoCAD |
| Excel ↔ CSV | 原生导出/导入 | 无 |
| 图片互转 | 图像处理库（`sharp`） | 无 |

> 转换功能**默认关闭**，作为扩展按需开启；无法自动转换的格式提供"关联程序打开"入口（此为唯一例外，非编辑路径）。

### 1.5 打包与分发（GitHub 工作流）

> **约定：软件打包一律通过 GitHub Actions 工作流进行**，不在本地手工打包。本地只做开发与调试（`dev` 模式），**可分发的安装包必须由 CI 产出**，以保证可复现、可追溯、跨平台一致。

| 项 | 选型 / 约定 | 说明 |
|----|-----------|------|
| 打包工具 | **electron-builder** | 产出 Windows 安装包（NSIS）、macOS `.dmg`、Linux `.AppImage`/`.deb` |
| 构建编排 | **GitHub Actions**（`.github/workflows/build.yml`） | push 到 `main` / 打 tag / 手动触发均触发构建 |
| 目标平台 | **Windows 为主**（`windows-latest`），macOS/Linux 可选（matrix） | 用户主环境为 Windows；其余平台按需启用 |
| 产物发布 | **GitHub Releases**（自动上传 artifacts + 生成 Release Notes） | 打 tag（如 `v0.1.0`）即自动发版 |
| 版本管理 | 语义化版本（`vX.Y.Z`），版本号写入 `package.json` | 每次发版递增（当前 `0.3.0`） |
| 应用图标 | **可爱小人整理文件夹**（`public/icon.png` + `icon.ico`） | `scripts/gen-icon.mjs` 矢量绘图 + 纯 Node 手写 PNG 编码（零依赖）生成，`derive-icons.mjs` 派生多尺寸；窗口/favicon/exe 图标统一用它 |
| 产物校验 | 附带**校验和（SHA-256）**与构建元数据 | 便于用户验证完整性 |

**工作流约定（实现方必须遵守）：**
1. 打包**只能**由 GitHub Actions 触发；本地 `pnpm run build` 仅用于开发自检，不产出分发物。
2. 工作流需覆盖：安装依赖 → 类型检查/单元测试 → electron-builder 打包 → 上传 artifacts → 打 tag 时创建 Release。
3. Windows 包需处理**代码签名占位**（当前无证书则跳过签名，但保留配置位）。
4. 每个 Release 必须可在干净机器上**一键安装并启动**，否则视为打包失败。

## 二、项目架构

### 2.1 系统定位

- **个人使用的本地项目资料管理工具**，非企业级平台。
- 与企业"全流程管控平台"互补：企业平台管**流程审批**，本系统管**个人资料**（编制、整理、保存、跟踪）。
- 核心用户：勘测工程公司专业负责人（岩土/测绘/水文/物探等）。
- 核心功能主线：**上传 · 修改 · 保存 · 下载**，全程在程序内完成。

### 2.2 数据模型

```
项目 (Project)
 ├─ 项目信息 (ProjectInfo)   ← 建项时填写的一组信息字段
 ├─ 阶段 (Stage)
 │   ├─ 阶段信息 (StageInfo) ← 该阶段的一组信息字段
 │   └─ 资料槽位 (Slot)       ← 名称 + 期望格式 + 模板文件 + 必要性/时限/审查属性
 │       └─ 文件实例 (File)    ← 用户按模板填写生成，或直接上传；含版本
 └─ ...
```

> **统一"信息"概念**：**项目**与**阶段**各自都带一组**信息字段**（`项目信息` / `阶段信息`），在建项/建阶段时填写、随项目保存。进度类字段由系统**自动计算**（见 2.2.3）。

#### 2.2.1 项目信息（建项时填写）

> **建项流程（v0.4.0）**：先**提示选择项目架构模板**（从全局模板库选一个作为骨架），再填写下方**新字段表单**，确认后生成自包含项目文件夹与 `project.json`。

| 字段 | 必填 | 说明 |
|------|------|------|
| 地区 | ✅ | 项目所在地区 |
| 名称 | ✅ | 项目显示名 |
| 阶段 | 选填 | 初始阶段（可由模板带入，可改） |
| 类型 | 选填 | 项目类型（如 勘测/设计/施工…） |
| 编号 | ✅ | 如 `60-F14742S` |
| 下发时间 | 选填 | 任务/文件下发时间 |
| 备注 | 选填 | |
| 项目进度 | **自动** | 见 2.2.3，随文件增删动态调整 |

#### 2.2.2 阶段信息（建/调阶段时填写）

| 字段 | 必填 | 说明 |
|------|------|------|
| 阶段名称 | ✅ | 预置阶段名可改 |
| 起始时间 | 选填 | 进入该阶段的时间 |
| 完成时间 | 自动/手填 | 该阶段全部必填槽位完成时自动标记 |
| 阶段进度 | **自动** | 见 2.2.3，随该阶段文件增删动态调整 |
| 说明 | 选填 | |

#### 2.2.3 进度计算规则（自动、动态）

> **原则**：进度**不是手填的死值**，而是由**槽位/文件的完成状态实时推导**；项目执行过程中**随时添加/修改/删除文件，进度自动重算**，不失真。

- **槽位完成度** = 该槽位"已有合格文件实例"？1 : 0（按必要性加权：必填槽位权重 > 应填 > 可选）。
- **阶段进度** = Σ(阶段内槽位完成度 × 权重) / Σ(阶段内槽位权重)。
- **项目进度** = Σ(阶段进度 × 阶段权重) / Σ(阶段权重)，阶段权重默认均等、可调。
- 触发重算时机：文件**上传/删除/状态变更/版本更新**后立即重算并持久化。

#### 2.2.4 关键关系与数据落盘

- 一个**项目**含多组**阶段**；一个**阶段**含多个**槽位**；一个**槽位**可挂多个**文件实例**（多版本）。
- **模板文件**挂在**槽位**上，是该槽位资料的"骨架"；用户基于模板填写生成**文件实例**。
- 所有配置与状态（项目信息/阶段/阶段信息/槽位/模板/文件状态/进度缓存）存于项目内 `project.json`，**数据与代码解耦** —— 增删阶段、加槽位、改模板、改信息字段均只改数据，不动代码。

### 2.3 预置阶段（可增删/自定义）

> 系统**预置**以下 6 个模块（勘测业务默认值），用户可**增、删、改名、调序、自定义**任意阶段。

| 序号 | 阶段 | 说明 |
|------|------|------|
| 1 | 项目立项 | 任务接收、合同关联、任务书 |
| 2 | 项目策划 | 大纲、QSHE、预算、分包（资料最密集） |
| 3 | 项目执行 | 工作量确认、试验结果、中间资料、安全记录 |
| 4 | 成果审查与归档 | 报告、图纸、计算书、签字盖章、强制性条文 |
| 5 | 结算与总结 | 结算材料、经验总结、安全文件汇编 |
| — | 跨阶段日常管理 | 申请表单、报销差旅、制度规范、系统操作（不绑定阶段） |

### 2.4 功能模块划分（可插拔）

> 每个功能是一个**独立模块**，统一接口、独立状态。P0 建立全部骨架，之后**按需逐个填充/增强**。

| 模块 | 职责 | 基础(P0) | 增强(后续) |
|------|------|----------|-----------|
| `project` | 项目创建/保存/加载/删除、根目录管理 | ✅ | 多项目对比、项目导入导出 |
| `stage` | 阶段增删/改名/调序、数据驱动渲染 | ✅ | 阶段模板包 |
| `slot` | 槽位增删改、模板挂载、元数据 | ✅ | 槽位模板库 |
| `template` | 模板上传、结构识别、字段模型生成 | ✅ | 识别规则增强、复杂文档 |
| `editor` | 程序内编辑（Word 原位替换 / Excel） | ✅ 基础 | OnlyOffice 兜底 |
| `file` | 上传/保存/版本/下载 | ✅ | 批量打包、按状态导出 |
| `status` | 状态流转、缺项提示、时限提醒 | ✅ 基础 | 提醒策略、归档提醒 |
| `search` | 检索、条件筛选 | 基础 | 全文 FTS5 |
| `convert` | 格式转换 | — | Word→PDF、CAD→PDF 等 |
| `classify` | **项目分类**：可扩展多维（地区/专业/客户…）元数据 + 视图分组/筛选/排序（**非物理目录嵌套**，见 2.9） | 已建立 | 多级联动、按分类统计 |

### 2.5 目录结构（文件夹自包含）

> 根目录由用户自选；每个项目一个自包含文件夹，可整体复制/搬移/备份。

```
数据根目录/                          ← 用户在设置中自选
 └─ 项目名_编号/                      ← 创建项目时生成
     ├── project.json                ← 项目元数据 + 阶段/槽位/模板/状态配置
     ├── templates/                  ← 模板文件（docx / xlsx）
     │    └─ 勘测大纲.docx
     ├── 01_项目立项/
     │    └─ ...文件实例（按槽位生成/上传）
     ├── 02_项目策划/
     ├── 03_项目执行/
     ├── 04_成果审查与归档/
     ├── 05_结算与总结/
     ├── 日常管理/
     └─ _backup/                      ← 自动版本备份（可选）
```

### 2.6 模板引擎（核心机制）

**工作流**：

```
① 上传模板文件(docx/xlsx)
        ↓
② 自动结构识别 → 生成"结构模型"
   （章节 / 字段 / 表格，按 Heading 样式·加粗大字·表格首行推断）
        ↓
③ 渲染为程序内可编辑表单（所有文字均可改）
        ↓
④ 用户填写/修改（原位替换文本，格式不动）
        ↓
⑤ 保存为文件实例（多版本）→ 下载/导出
```

**保真保证**：编辑只替换文档 XML 中的文本节点，样式/字体/表格/页边距**零改动**，故"下载结果与模板格式一致"。

**中文健壮性**：全链路 UTF-8；兼容中文标签、全角冒号、无占位符的空白下划线；CJK 换行/字数单独处理。

### 2.8 源码分层与去重（实现约定）

> 原则：**单一职责、跨层共享、杜绝重复**。三处易重复的逻辑统一收到共享模块，避免"渲染层一份、主进程一份"。

| 层 | 位置 | 职责 | 约束 |
|----|------|------|------|
| 渲染层 | `src/` | Vue 3 + Element Plus UI（App / components / stores / types） | 只经 `window.api`（preload 桥）访问本地能力，不直接 import electron |
| 主进程 | `electron/` | `main` / `preload` / `ipc` + `services`（docx·xlsx 引擎、模板服务、`fs` 助手） | 引擎与 IPC 只在此层 |
| 共享层 | `shared/` | `types` / `paths` / `template-mapping` / `util` | **纯逻辑、零 electron 依赖**，渲染层与主进程均可安全 import；单元测试也 import 它 |

**去重落点：**
- `shared/template-mapping.ts` → `projectToTemplateStages`、`countTemplateSlots`（ProjectList 与 TemplateManager 共用，不再各写 `slotCount`）。
- `shared/util.ts` → `formatDateTime`、`nowIso`（FilePanel 与 TemplateManager 共用，不再各写 `fmt`）。
- `electron/services/fs.ts` → `ensureDir`、`copyFile`（ipc.ts 与 template-service.ts 共用，不再各写一份）。
- 单元测试合并为单一 `test/unit.test.ts`（Word 原位替换保真 4 项 + 模板映射 3 项，共 7 项），不再拆两个文件。

### 2.9 项目分类（可扩展多维 · 视图层，非物理目录）

> **定位**：分类是**项目的一个数据属性 + 列表视图**，**不是物理目录嵌套**。项目文件夹仍保持"自包含、扁平、可整体搬移"的根基（见 2.5），分类只改变**怎么组织/查找项目**，不改变**项目怎么存放**。

**核心决策（已拍板）：**
1. **分类 = 元数据（方案 A）**：给项目加一组"维度 → 取值"的键值对；列表按所选维度**分组 / 筛选 / 排序**。物理目录**不变**，仍是 `根目录/项目名_编号/`。
2. **维度可扩展、用户自定义**：维度不是写死的，而是用户在界面上**增 / 删 / 改名**任意多个（如"地区""专业""客户""年份"…），一次定义、全项目通用。系统**不预置**任何业务维度（符合"不预置业务内容"原则）。
3. **取值自由文本**：每个维度下，每个项目填一个**取值**（自由文本，如"地区=华北"）。不做级联/枚举约束，保持灵活。

**数据落盘：**
- **维度定义**（哪些维度、叫什么）：存于**数据根目录**下的 `ppims.json`（根级配置，全局唯一），形如：
  ```json
  { "dimensions": [ { "id": "dim_x", "name": "地区" }, { "id": "dim_y", "name": "专业" } ] }
  ```
- **项目取值**（某项目在各维度的取值）：存于该项目 `project.json` 的 `info.categories`，形如 `{ "dim_x": "华北", "dim_y": "岩土" }`（维度 id → 取值）。
- 删除某维度时，`ppims.json` 移除该维度定义；各项目 `info.categories` 里对应的残留取值键**惰性清理**（下次保存该项目时清除，不强制批量改所有项目）。

**使用灵活性：**
- 新建项目时，表单**动态渲染**当前所有维度的取值输入（维度为空则不显示分类区）。
- 项目列表默认按"全部"平铺；点选某维度即按其取值**分组**；可叠加**筛选**（某维度=某取值）与**排序**（按某维度取值 / 立项时间）。
- 分类**不影响**项目内部结构、进度计算、模板套用——纯组织维度。

**去重落点：** 维度校验 / 默认取值 / 取值清理等纯逻辑统一收 `shared/classify.ts`（零 electron 依赖，可单测）；`ppims.json` 读写在主进程 `ipc.ts`。

## 三、阶段进度

> **原则**：P0 一次性建立**全部基础骨架**（所有核心功能可用），之后**按功能逐个填充/增强**，不锁定顺序。**灵活是本软件最大优点** —— 任何功能可提前、延后、插队，架构不受影响。

### 3.1 P0 地基（一次性建立，全部核心功能可用）

P0 交付后系统即可完整跑通"建项目 → 设阶段 → 挂模板 → 填写/上传 → 保存 → 下载"主闭环。

| 模块 | P0 交付内容 | 状态 |
|------|-----------|------|
| `project` | 项目创建/保存/加载/删除、根目录自选、文件夹生成、**提示选模板 + 新字段表单**（地区/名称/阶段/类型/编号/下发时间/备注） | ⬜ 待开发 |
| `stage` | 6 阶段预置 + 增删/改名/调序、**阶段信息字段**（名称/起止时间等） | ⬜ 待开发 |
| `slot` | 槽位增删改、模板挂载、元数据（名称/格式/必要性/时限/审查属性） | ⬜ 待开发 |
| `template` | 模板上传、结构识别、字段模型、可编辑表单 | ⬜ 待开发 |
| `editor` | Word 原位替换编辑、Excel 编辑、中文健壮 | ⬜ 待开发 |
| `file` | 上传/保存/版本/单文件下载 | ⬜ 待开发 |
| `status` | 状态流转（待编/编制中/待审/已审/已归档）、缺项提示、**进度自动计算（随文件增删动态重算）** | ⬜ 待开发 |
| `search` | 文件级检索、条件筛选 | ⬜ 待开发 |

**P0 验收标准（全部满足才算 P0 完成）：**
1. 在自选根目录下**新建项目**：先**选择项目架构模板**，再**填写新字段表单**（地区/名称/阶段/类型/编号/下发时间/备注），自动生成自包含项目文件夹与 `project.json`；**重启应用后能正确加载**该项目及其项目信息。
2. 项目内**预置 6 阶段**，可**增、删、改名、调序**，并填写**阶段信息**；修改即时持久化且重启不丢失。
3. 在某阶段下**新增槽位**并挂一个 Word 模板，系统**自动识别出章节/字段**并渲染成可编辑表单。
4. 在表单中**修改文字**后保存，导出的 docx **与原模板格式一致**（样式/字体/表格零变化），修改内容正确写入。
5. 可**直接上传**现成文件到槽位；可**下载**单个文件；文件**多版本**可回溯。
6. **添加/删除/变更状态**某文件后，**阶段进度与项目进度自动重算**，数值随完成度实时变化且不失真。
7. 全流程**不跳转第三方程序**完成；中文输入/显示/保存**无乱码、无截断**。
8. 通过 **GitHub Actions 打包**出 Windows 安装包，在干净机器**一键安装可启动**。

### 3.2 功能状态板（P0 后按需填充，顺序不锁定）

> 以下为**候选功能池**，非固定路线图。每项独立、可插拔，状态随开发推进更新：`待开发 → 开发中 → 已完成 → 已增强`。

| 功能 | 所属模块 | 说明 | 验收标准（达成=完成） | 状态 |
|------|---------|------|----------------------|------|

| OnlyOffice 复杂文档兜底 | `editor` | 复杂图文/嵌套表格完美编辑 | 复杂文档可完整编辑且导出与原格式一致 | 待开发 |
| 全文检索（FTS5） | `search` | 跨项目/跨文件内容检索 | 输入关键词命中文件正文，结果可点击定位 | 待开发 |
| 格式转换（Word→PDF 等） | `convert` | 依赖本地 Office/CAD | 一键转换成功，产物可打开；依赖缺失时给出明确提示 | 待开发 |

### 3.3 进度度量

- **完成 = 达成验收标准**：任一阶段/功能标记"已完成"，必须已满足其对应验收标准，且可复现。
- **模块完成度** = 该模块 P0 交付内容已完成项 / P0 交付内容总数。
- **功能完成度** = 功能状态板中"已完成/已增强"项 / 已启动项。
- **P0 整体完成度** = P0 验收标准 9 条中已达成条数 / 9。
- 每次推进更新上表状态列，保证"整个项目完成进程清晰条理"。

## 四、扩展延伸

> 以下为**远期/可选**能力，不影响 P0 架构。均设计为**可插拔模块**，启用时不改动核心。

### 4.1 编辑能力增强

- **OnlyOffice Document Server 嵌入**：复杂文档完美编辑兜底（独立进程，按需启动）。
- **CAD 预览**：程序内查看 dwg（只读），编辑仍走 CAD（系统负责收进来统一管理）。
- **PDF 标注/预览**：只读为主，支持标注、转图。

### 4.2 智能识别增强

- **字段识别规则库**：沉淀"中文标签 → 字段"映射规则，提高自动识别准确率。
- **模板相似度**：识别新模板时匹配已有结构模型，复用字段定义。

### 4.3 数据与协同

- **多项目仪表盘**：跨项目进度、缺项、超期汇总视图。
- **企业平台对接**（远期）：本系统整理完的资料一键导出为平台所需格式，减少重复录入。
- **模板市场**（远期）：团队内共享常用模板/槽位包。

### 4.4 安全与备份

- **本地加密**：敏感资料可选加密存储。
- **增量备份**：基于版本链的增量备份，降低 `_backup` 体积。
- **操作日志**：关键操作（删除/覆盖/导出）留痕。

### 4.5 多端与分发

- **便携模式**：单文件夹绿色版，U 盘即用（Electron portable）。
- **移动端只读**（远期）：H5 只读查看项目进度与资料清单。
